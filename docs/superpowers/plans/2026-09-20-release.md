# September 20 release

## Scope and contract

Publish the verified current main as the next Black Box release. Keep the release pre-1.0 unless
an explicit stable API/schema contract and supported upgrade policy are adopted. Version the
Maven artifact, MCP metadata, frontend package, and active JAR consumers together. Leave historical
artifacts and independent test fixtures at their original versions. Do not format existing Java,
deploy locally, change infrastructure, or touch unrelated worktrees.

## Verification and publication

- Run Maven verification, frontend checks, and packaged browser/coordination flows in this isolated
  checkout. Rehearse an upgrade using the actual 0.1.0 release and a disposable SQLite database.
- Review the version-only consumer edits, release notes, and workflow. The release workflow verifies
  its tag matches Maven, runs Java verification, and publishes a JAR plus checksum.
- Push the narrow release preparation branch, merge after green checks, tag the verified commit,
  and inspect the published assets. Verify the downloaded artifact and checksum before completion.
- Record actual outcomes here and in the existing private Black Box note. No local deployment.

## Results

- Maven verify: 637 tests, no failures/errors, 18 skipped by their existing conditions.
- Frontend: 610 tests passed; the packaged browser run also type-checks and rebuilds the UI.
- Benchmark harness: 27 offline tests passed after its artifact path update.
- Exact published 0.1.0 JAR checksum verified. Disposable SQLite upgrade preserved two captured
  event IDs and their text; a new capture was recalled after upgrade. Matched backup plus old JAR
  restored the original records at a fresh path. The initial restore harness reused a database
  path with stale WAL state; correcting the fixture and closing its backup connections resolved
  that harness error. Upgrade docs explicitly require a fresh restore path.
- Independent review accepted version alignment and workflow; corrected standalone JAR instructions
  to select the local summary fallback because external wrapper scripts are repository-only.
- Packaged Playwright suite: 24/24 passed. Its first run exposed eight stale selectors from
  earlier UI changes (Options disclosure, suggestion option roles, exact-event links, duplicated
  session/event text). Updated only the tests to follow the current UI while retaining behavior
  assertions. Independent review accepted the corrections. No application code changed.
- Authenticated browser smoke passed login, read, real spec/task creation with CSRF, logout, and
  anonymous denial. All 431 existing Java source files remain byte-identical to pre-release main.
- Isolated browser and upgrade servers were stopped; the existing live-service PID was unchanged.
- PR CI and tagged publication are the remaining release gates. The published release and its
  Actions record are authoritative for publication status.
