# Black Box 0.2.0

Black Box is a local-first memory bus for coding agents: capture a decision or handoff, then recall
that structured context from another session through MCP, REST, or the web UI. This release gathers
the work since June's 0.1.0 into a new runnable artifact.

## Highlights

- **Recall across sessions.** Hybrid lexical and optional semantic retrieval over Decisions,
  Handoffs, and Observations, with bounded results, a relevance floor, and lexical fallback.
  The Recall UI adds 90- and 180-day windows and keyboard-accessible search help.
- **A clearer history.** The SolidJS Activity workspace includes full-text search, facets, saved
  views, complete transcript browsing, and subagent lineage. Project trajectories distinguish
  recorded evidence from speculative projections.
- **Coordination with explicit ownership.** Frozen specifications, atomic task claims, validated
  transitions, and completion Handoffs are available through matching REST and MCP operations.
  The optional runner is a separate process with repository and shipping safeguards.
- **Recoverable local operation.** An opt-in durable hook outbox retries captures safely, unfinished
  runner work is retained, and local deployment verifies immutable artifacts with binary recovery.
- **Inspectable evidence.** Evaluation harnesses and sanitized results document both improvements
  and negative results. They do not establish a general agent-productivity benefit. Offline
  lifecycle rehearsal cannot provision or destroy infrastructure.
- **Maintainer tooling.** Enforced Java module boundaries, cross-runtime query fixtures, and an
  opt-in Spotless/Palantir formatter. Existing application Java sources were not reformatted.

## Download and run

Download `sba-agentic-0.2.0.jar` and `SHA256SUMS` from this release into the same directory. Java 21+
includes everything needed for the default local SQLite server; Elasticsearch and models are optional.

```bash
shasum -a 256 -c SHA256SUMS       # macOS; on Linux use sha256sum -c SHA256SUMS
SBA_SUMMARY_BACKEND=local SBA_LOCAL_AI_ENABLED=false java -jar sba-agentic-0.2.0.jar
```

The server binds to `127.0.0.1:8766`. The default database is `sba-agentic.db` in the working
directory. Keep that directory intentional and stable, or set `SBA_DATASOURCE_URL` to the desired
SQLite database. The bundled UI needs no Node installation.

The command above uses compacted-transcript summaries without a model. To generate summaries with
a local OpenAI-compatible model, configure its endpoint and enable `SBA_LOCAL_AI_ENABLED`.
The external summary backend requires the repository-supplied wrapper script and its configured
provider CLI; those scripts are not included in the standalone JAR.

## Upgrade from 0.1.0

1. Stop the recorder and any separate runner before replacing their binaries. Retain the old JAR,
   service configuration, and a verified backup of the canonical database. For SQLite, stop all
   writers and use SQLite's backup facility; do not copy only the main file of an active WAL database.
2. Start 0.2.0 with the same intended database and configuration. Startup performs additive schema
   initialization. This is not a versioned migration or rollback framework.
3. Check `/api/status`, browse retained history, and perform a small capture-and-recall check before
   restarting hooks or runners. Service definitions with an explicit `0.1.0` JAR path must be updated.
4. If recovery is necessary, stop the new process and restore a matched old binary, configuration,
   and database backup. Restore SQLite to a fresh path so stale WAL/SHM files cannot be replayed
   against the restored main file. Binary rollback alone does not reverse schema changes or new writes.

A disposable rehearsal using the published 0.1.0 JAR retained a Decision and Handoff through
upgrade, captured and recalled a new Handoff, and restored the original records using the old JAR
and a matching backup at a fresh database path. This checks a small SQLite fixture; it is not a
guarantee for every database or a PostgreSQL upgrade test.

For the source checkout's macOS deployment helper, follow
[Operations](https://github.com/nathanmauro/black-box/blob/v0.2.0/docs/operations.md).
Publishing this release does not update an existing local installation.

## Release boundaries

This is a pre-1.0 release. The core capture-and-recall loop is usable, but there is no long-term
API/schema stability promise or general downgrade guarantee. A 1.0 release should define that
compatibility contract and its supported upgrade paths explicitly.

SQLite remains the default canonical store. The opt-in PostgreSQL profile uses its own database;
there is no automatic SQLite/PostgreSQL synchronization or support for multiple API replicas.
The former AWS prototype has been retired. This release does not provide a hosted service.

The default loopback server has no authentication. Exposing it to a network requires the optional
authentication boundary and HTTPS. The source checkout defaults to its external Codex wrapper,
which can send transcript text to a vendor; set `SBA_SUMMARY_BACKEND=local` to select a local
OpenAI-compatible model instead. Optional integrations remain subject to their own configuration.

Semantic recall covers structured Decisions, Handoffs, and Observations; Projections are recalled
lexically. Full event history is searchable but is not entirely semantically indexed.
