# Black Box 0.3.0

Black Box is a local-first memory bus for coding agents: capture structured Decisions, Handoffs,
Observations, Ideas, and Evidence, then recall that context across sessions through MCP, REST, CLI,
or the web UI. This release gathers the architecture, capture-fidelity, diagnostics, redaction,
recovery, UI, onboarding, and performance work landed since [v0.2.0](v0.2.0.md).

## Highlights

- **Focused memory bus; task board, runner, and Jev/Cortex judge removed.** Session parent/child
  relationships and DAGs live in the `lineage` module, while the dormant `/board` UI, task/spec
  REST routes, workflow MCP tools, separate `runner` process, and optional Jev/Cortex judgment
  stage are removed ([board retirement](../board-retirement.md)). Issue trackers own task queues;
  Black Box owns cross-session agent evidence and continuity.
- **Richer structured intent, ADR export, and deterministic continuations.** Capture and recall
  cover `Idea` (`captureIdea` with stable `ideaKey` status updates and verbatim quotes) and
  `Evidence` (`captureEvidence` with provenance and supporting/refuting links) alongside Decisions,
  Handoffs, and Observations. Related sessions group across repositories as
  [projectless braids](../projectless-braids.md), `GET /api/continuations` builds bounded
  deterministic **Prompts from the record** with no model call, Recall cards include **Copy ADR**,
  and `./scripts/blackbox export-adr` renders project Decisions into Markdown ADRs with Git drift
  checks.
- **One-flag offline profile, unified CLI, and `black-box` artifact/MCP naming.** Added the
  `offline` Spring profile (`--spring.profiles.active=offline`) disabling external/model calls in
  one flag, `./scripts/blackbox` (`start`, `status`, `demo`, `init`, `export-adr`), and a bundled
  portable agent skill (`skills/black-box/SKILL.md`). The Maven artifact and MCP server now publish
  as `black-box` (`black-box-0.3.0.jar`); existing clients registered under the historical
  `sba-agentic` alias and `SBA_*` environment variables continue working unchanged.
- **Zero-model handoff summaries and deeper credential protection.** When a session records a
  structured Handoff, session finalization promotes that Handoff directly as its summary
  (`summary_source = handoff`) with zero model latency or token cost. The hook bridge streams large
  payloads to `jq` over stdin instead of hitting `ARG_MAX`, preserves Claude `Stop` assistant turns
  through search and transcript merges, masks Black Box's own configured credential values across
  every display and encoded shape (including Base64 streams), and redacts stored text before
  summary or meld calls.
- **Diagnostics, continuity linting, braid-graph export, and offline recall regression benchmark.**
  Added read-only `GET /api/diagnostics/storage` ([storage diagnostics](../storage-diagnostics.md)),
  `GET /api/diagnostics/continuity` and redacted `GET /api/export/braid-graph` (JSON or Mermaid,
  [continuity diagnostics](../continuity-diagnostics.md)), and the offline synthetic
  [recall quality benchmark](../recall-benchmark.md) (`scripts/recall-benchmark.sh`).
- **Ambient surfaces, custom PWA icons, and faster human review.** Added the chrome-less
  `/companion` view and optional native macOS panel ([companion](../companion.md)), the optional
  macOS menu-bar quick-recall helper ([macOS quick recall](../macos-quick-recall.md)), custom app
  icons and `manifest.webmanifest`, **My Turns** inline follow-up expansion, live
  **Project Windows** cards, caret-aware stream query completion, and a scripted throwaway-DB
  [live demo](../live-demo.md).
- **Encrypted offsite backups, fast shutdown, and measured hot paths.** The standalone
  [backup CLI](../database-recovery.md) copies live WAL SQLite databases in a single consistent
  step, `scripts/storage/blackbox_offsite_backup.py` encrypts offsite snapshots with AES-256 and
  restore verification, SQLite read-write transactions begin `IMMEDIATE`, SSE clients resume via
  durable `Last-Event-ID` cursors without blocking graceful shutdown (`32.1 s` to `~1.1 s`), and
  hot paths carry reproducible benchmarks for
  [transcript deduplication](../performance/transcript-deduplication.md),
  [batched lineage metadata](../performance/lineage-metadata.md),
  [timestamp-indexed dashboard activity](../performance/dashboard-activity-range.md),
  [lazy stream payloads](../performance/stream-payload-work.md),
  [on-demand route loading](../performance/frontend-route-loading.md), and
  [frontend request budgets](../performance/frontend-request-budgets.md).

## Download and run

Download `black-box-0.3.0.jar` and `SHA256SUMS` from GitHub Releases into the same directory.
Java 21+ includes everything needed for the default local SQLite server; Elasticsearch and models
remain optional.

```bash
shasum -a 256 -c SHA256SUMS       # macOS; on Linux use sha256sum -c SHA256SUMS
java -jar black-box-0.3.0.jar --spring.profiles.active=offline
```

The server binds to `127.0.0.1:8766` and stores `sba-agentic.db` in the working directory unless
`SBA_DATASOURCE_URL` overrides it. With `--spring.profiles.active=offline`, sessions that record a
structured Handoff receive deterministic `handoff` summaries; other finalized sessions fall back to
compacted-transcript summaries without calling a model.

To build from source instead, run `mvn -q -DskipTests package` in an isolated checkout following
[Installation](../installation.md) and [Operations](../operations.md).

## Upgrade from 0.2.0

1. Stop the running `0.2.0` server and any separate `0.2.0` runner process before replacing
   binaries. Do not start an old runner against the updated server. Take a verified native backup
   first using `python3 scripts/storage/blackbox_backup.py` (see
   [Database recovery](../database-recovery.md)) and retain your `0.2.0` JAR and service definition.
2. Start the new build against the intended database and configuration. Existing databases retain
   session lineage and historical Handoffs automatically while leaving legacy task tables untouched
   by default. Dropping legacy `specs`/`tasks`/`task_events` tables via `SBA_RETIRE_WORKFLOW=true`
   is optional, explicit, and one-way; read [Board retirement](../board-retirement.md) before
   enabling it.
3. Reload or reconnect cached MCP clients so retired workflow tools (`createSpec`, `enqueueTask`,
   `claimNextTask`, `updateTaskStatus`, `completeTask`, `listTasks`, `getSpec`) are cleared from
   their tool inventory and newer continuity tools (`captureIdea`, `captureEvidence`, braids) load.
   Verify `/api/status` and run a small capture-and-recall smoke check before resuming normal hooks.
4. If rollback is required and `SBA_RETIRE_WORKFLOW=true` was **not** run, stop the new process and
   restore the matched `0.2.0` binary, configuration, and pre-upgrade snapshot at a fresh SQLite
   path so stale `-wal`/`-shm` files cannot replay against the restored file. Never point a `0.2.0`
   JAR at a database migrated with `SBA_RETIRE_WORKFLOW=true`.

## Release boundaries

This remains a pre-1.0 project. The capture-and-recall loop is tested and used daily, but APIs and
schemas do not yet carry a long-term compatibility or general downgrade guarantee.

SQLite is the default canonical store. The optional PostgreSQL profile owns a separate database for
a single API instance; selecting a profile does not synchronize SQLite and PostgreSQL history or
support horizontal API replicas ([PostgreSQL](../postgres-backend.md)).

The default loopback server disables authentication. Network exposure requires enabling the
[authentication boundary](../authentication.md) behind HTTPS. Source checkouts default session
summaries to the external Codex wrapper, which can send redacted transcript excerpts to a vendor;
set `SBA_SUMMARY_BACKEND=local` to keep summarization on a local OpenAI-compatible endpoint or off
entirely.

Semantic recall indexes structured intent (`Decision`, `Handoff`, `Observation`, `Idea`,
`Evidence`); Projections and full session event streams are searched lexically via SQLite FTS5 or
PostgreSQL search rather than full-corpus vector indexing.
