# Black Box 0.3.0 (Draft)

> Draft release notes for the next runnable release after [v0.2.0](v0.2.0.md). Source on `main` already includes the changes below, while `pom.xml` remains at `0.2.0` until the `v0.3.0` tag is cut. Build from source for these changes today; when cutting `v0.3.0`, bump the packaged version to `0.3.0`, remove this draft notice, and switch the comparison link at the bottom to `v0.2.0...v0.3.0`.

Black Box is a local-first memory bus for coding agents: capture structured Decisions, Handoffs,
Observations, Ideas, and Evidence, then recall that context across sessions through MCP, REST, CLI,
or the web UI. This draft gathers the architecture, capture-fidelity, recovery, UI, and performance
work landed on `main` since September's `0.2.0` release.

## Highlights

- **Focused memory bus; task board and runner retired.** Session parent/child relationships and
  DAGs now live in a dedicated `lineage` module, while the dormant `/board` UI, task/spec REST
  routes, workflow MCP tools, and separate `runner` process are removed
  ([board retirement](../board-retirement.md)). Issue trackers own task queues; Black Box owns
  cross-session agent evidence and continuity.
- **Richer structured intent and deterministic continuations.** Capture and recall now cover `Idea`
  (`captureIdea` with stable `ideaKey` status updates and verbatim quotes) and `Evidence`
  (`captureEvidence` with provenance and supporting/refuting links) alongside Decisions, Handoffs,
  and Observations. Related sessions can be grouped across repositories as
  [projectless braids](../projectless-braids.md), and `GET /api/continuations` builds bounded,
  deterministic **Prompts from the record** without calling a model (with optional local-only
  restatement off by default).
- **Zero-model handoff summaries and safer capture pipelines.** When a session records a structured
  Handoff, session finalization promotes that Handoff directly as the session summary
  (`summary_source = handoff`) with zero model latency or token cost. The hook bridge streams large
  payloads to `jq` over stdin instead of hitting `ARG_MAX`, preserves Claude `Stop` assistant turns
  through full-text search and transcript merges, and applies expanded credential redaction across
  service configurations, tool JSON, and summary inputs.
- **Ambient surfaces and faster human review.** Added the chrome-less `/companion` view and optional
  native macOS panel ([companion](../companion.md)), an optional macOS menu-bar quick-recall helper
  ([macOS quick recall](../macos-quick-recall.md)), a **My Turns** human-prompt filter with inline
  follow-up expansion, live **Project Windows** cards per active project, and caret-aware stream
  query completion.
- **Recoverable storage, fast shutdown, and measured hot paths.** The standalone
  [backup CLI](../database-recovery.md) copies live WAL SQLite databases in a single consistent step
  (with an optional nightly backup script and Slack failure alert), SQLite read-write transactions
  begin `IMMEDIATE` so concurrent writes wait on `busy_timeout`, SSE clients resume via durable
  `Last-Event-ID` cursors without blocking graceful shutdown (`32.1 s` to `~1.1 s`), and hot paths
  carry reproducible benchmarks for
  [transcript deduplication](../performance/transcript-deduplication.md),
  [batched lineage metadata](../performance/lineage-metadata.md),
  [timestamp-indexed dashboard activity](../performance/dashboard-activity-range.md),
  [lazy stream payloads](../performance/stream-payload-work.md),
  [on-demand route loading](../performance/frontend-route-loading.md), and
  [frontend request budgets](../performance/frontend-request-budgets.md).

## Download and run (once `v0.3.0` is tagged)

When `v0.3.0` is published on GitHub Releases, download `sba-agentic-0.3.0.jar` and `SHA256SUMS`
into the same directory. Java 21+ includes everything needed for the default local SQLite server;
Elasticsearch and models remain optional.

```bash
shasum -a 256 -c SHA256SUMS       # macOS; on Linux use sha256sum -c SHA256SUMS
SBA_SUMMARY_BACKEND=local SBA_LOCAL_AI_ENABLED=false java -jar sba-agentic-0.3.0.jar
```

The server binds to `127.0.0.1:8766` and stores `sba-agentic.db` in the working directory unless
`SBA_DATASOURCE_URL` overrides it. With `SBA_LOCAL_AI_ENABLED=false`, sessions that record a
structured Handoff still receive deterministic `handoff` summaries; other finalized sessions fall
back to compacted-transcript summaries without calling a model.

Until `v0.3.0` is tagged, build from an isolated source checkout (`mvn -q -DskipTests package`)
following [Installation](../installation.md) and [Operations](../operations.md).

## Upgrade from 0.2.0

1. Stop the running `0.2.0` server and any separate `0.2.0` runner process before replacing
   binaries. Do not start an old runner against the updated server. Take a verified native backup
   first using `python3 scripts/storage/blackbox_backup.py` (see
   [Database recovery](../database-recovery.md)) and retain your `0.2.0` JAR and service definition.
2. Start the new build against the intended database and configuration. Existing databases retain
   session lineage and historical Handoffs automatically while leaving legacy task tables untouched
   by default. Dropping legacy `specs`/`tasks`/`task_events` tables via `SBA_RETIRE_WORKFLOW=true`
   is optional, explicit, and one-way; read [Board retirement](../board-retirement.md) before
   enabling it.
3. Reload or reconnect cached MCP clients so retired workflow tools (`createSpec`, `enqueueTask`,
   `claimNextTask`, `updateTaskStatus`, `completeTask`, `listTasks`, `getSpec`) are cleared from
   their tool inventory and newer continuity tools (`captureIdea`, `captureEvidence`, braids) load.
   Verify `/api/status` and run a small capture-and-recall smoke check before resuming normal hooks.
4. If rollback is required and `SBA_RETIRE_WORKFLOW=true` was **not** run, stop the new process and
   restore the matched `0.2.0` binary, configuration, and pre-upgrade snapshot at a fresh SQLite
   path so stale `-wal`/`-shm` files cannot replay against the restored file. Never point a `0.2.0`
   JAR at a database migrated with `SBA_RETIRE_WORKFLOW=true`.

## Release boundaries

This remains a pre-1.0 project. The capture-and-recall loop is tested and used daily, but APIs and
schemas do not yet carry a long-term compatibility or general downgrade guarantee.

SQLite is the default canonical store. The optional PostgreSQL profile owns a separate database for
a single API instance; selecting a profile does not synchronize SQLite and PostgreSQL history or
support horizontal API replicas ([PostgreSQL](../postgres-backend.md)).

The default loopback server disables authentication. Network exposure requires enabling the
[authentication boundary](../authentication.md) behind HTTPS. Source checkouts default session
summaries to the external Codex wrapper, which can send redacted transcript excerpts to a vendor;
set `SBA_SUMMARY_BACKEND=local` to keep summarization on a local OpenAI-compatible endpoint or off
entirely.

Semantic recall indexes structured intent (`Decision`, `Handoff`, `Observation`, `Idea`,
`Evidence`); Projections and full session event streams are searched lexically via SQLite FTS5 or
PostgreSQL search rather than full-corpus vector indexing.
